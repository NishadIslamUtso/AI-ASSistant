## 2026-10-14 (night) — the port the browser extension posts to

**Built:** `src/main/extension/server.ts` — a second loopback listener on 127.0.0.1:8765
(`AI_ASSISTANT_EXTENSION_PORT` overrides it), with its own origin rule and a deliberately tiny route
table: health, status, context, capsules, blacklist, capture. Settings > System names the port, and the
app states it in the log at startup. `src/main/api/body.ts` is now the one body reader both servers use.

**Why a second listener:** the app's own API is served to its window and answers only its own origin, on
purpose. The extension is a separate program with no discovery mechanism, so it gets a fixed port — and
that port is acceptable because of what it can do, not because of who asks: no chat (an extension must
never be able to spend a saved key), no settings, no export, JSON writes only, the same 20 MB ceiling,
loopback only. Any `chrome-extension://` origin is answered, since an id only exists once installed; a
web page cannot pass at all, and a refusal carries no CORS headers.

**Verified:** 26 files / 242 tests, typecheck clean, both builds clean, smoke `errors=0 warnings=0`;
desktop end-to-end (`shot-tools/check-extension-port.cjs`) green in 1.6 s — a captured conversation lands
in the vault as Markdown, the never-check list round-trips including the extension's own writer shape
(`type: 'blacklist_update'`), a page origin and a bare request are both 403, `/chat` on that port is 404,
and Settings > System shows `Listening at 127.0.0.1:<port>`, console clean; the browser (33/33), vault
(6.3 s) and cloud (4.1 s) checks all still green on the same build.

**Landing:** this commit on `arena/3c06e1bf-ai-assistant-v3`, merged into `main`.
